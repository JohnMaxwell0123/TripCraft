## 2. 优先级与阶段定义

- **P0（必需，阶段 1–2）**：产品基线的主线闭环——对话与需求画像、路径 A、多人共享与多端同步、首批线路上架（阶段 1）；路径 B 匹配与筛选、AI 路书、咨询与报价、白标交付（阶段 2）。
- **P1（次要，阶段 2–3）**：体验增强与行中能力——自带模型 API、筛选增强、协作增强、离线单文件、车机投递、路线动画。
- **P2（探索，阶段 4–5）**：座舱深度协同、旅后回忆录与生态连接。

- **目标**：提供类似通用大模型聊天的对话入口；支持平台默认模型与用户自带模型 API；所有模型输出进入统一校验管线。

- **设计依据**：[docs/16 §16.2](../16-planning-paths-and-route-matching.md#162-对话入口与模型选择)、[ADR-009](../architecture/adr/ADR-009-llm-provider-byok.md)

#### F-M15-01 对话界面与模型选择器
- **优先级/阶段**：P0 / 阶段 1 ｜ **端**：C-MOBILE, C-WEB ｜ **模块**：M15
- **用户故事**：作为用户，我想像用聊天机器人一样直接说出旅行想法，并能看到当前用的是哪个模型。
- **验收标准**：
  1. Given 用户打开 App，When 进入首页，Then 看到对话输入框、零输入药丸与附件入口；输入框左侧显示当前模型与剩余额度。
  2. Given 用户上传攻略截图或 PDF，When 发送，Then 内容作为素材进入追问流程（[§8.3.3](../08-socratic-interaction-design.md#833--模式-c--素材投喂readme-未覆盖)）。
  3. Given 当前模型调用失败，When 返回错误，Then 显示失败原因与可选操作，不静默切换模型。
- **依赖**：F-M01-01 ｜ **设计/实现状态**：草案 / 无

#### F-M15-02 自带模型 API（BYOK）接入与能力检测
- **优先级/阶段**：P1 / 阶段 2 ｜ **端**：C-MOBILE, C-WEB ｜ **模块**：M15
- **用户故事**：作为已有模型订阅的用户，我想用自己的 API 来对话和规划。
- **验收标准**：
  1. Given 用户添加 OpenAI 兼容或 Anthropic 接口的 Key，When 保存，Then 执行能力检测，并展示“是否支持行程生成”的结论。
  2. Given Key 已保存，When 检查服务端存储与日志，Then 不存在该 Key 的任何副本（Key 仅存于设备加密存储）。
  3. Given 自带模型的服务商在境外，When 首次使用，Then 告知对话内容将发送至该服务商。
- **依赖**：F-M15-01, F-M15-04 ｜ **设计/实现状态**：草案 / 无

#### F-M15-03 平台模型额度计量与提示
- **优先级/阶段**：P0 / 阶段 1 ｜ **端**：S-AI 后端, C-MOBILE ｜ **模块**：M15
- **用户故事**：作为平台，我想对平台模型的调用设置额度，以便控制推理成本；作为用户，我想知道还剩多少额度。
- **验收标准**：
  1. Given 用户使用平台模型，When 每次调用完成，Then 按调用计量扣减额度，并在输入框旁更新剩余次数。
  2. Given 额度用完，When 用户继续发送，Then 提示“可订阅，或添加自己的 API”；已形成的画像与行程不受影响。
- **依赖**：F-M15-01 ｜ **设计/实现状态**：草案 / 无

#### F-M15-04 模型请求发送前的隐私脱敏
- **优先级/阶段**：P0 / 阶段 1 ｜ **端**：C-MOBILE, C-WEB ｜ **模块**：M15
- **用户故事**：作为用户，我不希望家人的姓名、证件号和手机号被发送给任何模型服务商。
- **验收标准**：
  1. Given 用户输入包含姓名、身份证号或手机号，When 向任何模型发起请求，Then 这些内容在客户端被替换为占位符（“一位长辈”“成员 A”）。
  2. Given 模型返回的内容包含占位符，When 在界面展示，Then 在本地还原为原文，原文不离开设备。
- **依赖**：无 ｜ **设计/实现状态**：草案 / 无

#### F-M16-01 骨架生成与分段车程校验
- **优先级/阶段**：P0 / 阶段 1 ｜ **端**：S-GENERATE, S-GEO ｜ **模块**：M16
- **用户故事**：作为自驾用户，我想先得到一个每天开车时间合理的整体路线，再看每天停哪。
- **验收标准**：
  1. Given 已确认的画像，When 生成骨架，Then 产出 2–3 个候选过夜城镇序列，每段车程经图商测算，超过日车程上限的候选被剔除。
  2. Given 所有候选都违反约束，When 返回结果，Then 指出是哪条约束卡住，并给出至少两种放宽选项，不输出违反约束的骨架。
- **依赖**：F-M03-05, F-M05-02 ｜ **设计/实现状态**：草案 / 无

#### F-M16-02 沿线走廊检索（景点 / 打卡点 / 美食 / 补给）
- **优先级/阶段**：P0 / 阶段 1 ｜ **端**：S-GEO ｜ **模块**：M16
- **用户故事**：作为自驾用户，我想知道沿途绕一点路就能到的好地方和好吃的。
- **验收标准**：
  1. Given 一段骨架路线，When 检索走廊，Then 返回绕行 ≤ 30 分钟（可配置）范围内的景区、观景打卡点、餐饮与补给点，均带图商 POI ID。
  2. Given 走廊检索使用了算路几何，When 检查写入行程 DSL 的数据，Then 不包含算路折线（[BR-025](../07-legal-and-compliance.md#781--br-025地图数据不得落库oi-003-收敛后的新增规则)）。
  3. Given 模型为餐饮节点撰写推荐语，When 写入 DSL，Then 店名、坐标、评分来自图商，推荐语写入 `advice`。
- **依赖**：F-M16-01, F-M05-01 ｜ **设计/实现状态**：草案 / 无

#### F-M16-03 每日编排与约束求解
- **优先级/阶段**：P0 / 阶段 1 ｜ **端**：S-GENERATE ｜ **模块**：M16
- **用户故事**：作为带老人孩子的组织者，我想每天的安排不累、吃饭和午休时间合理。
- **验收标准**：
  1. Given 候选 POI 与画像，When 编排一天，Then 车程 + 游览 + 餐点窗口 + 儿童午休不超过当天时间预算；按出行日期校验开放时间。
  2. Given 某 POI 开放信息缺失，When 编入行程，Then 标记 `tentative` 并说明原因。
  3. Given 编排完成，When 输出草案，Then 通过 `trip.schema.json` 校验与 BR 规则校验后才展示给用户。
- **依赖**：F-M16-02, F-M02-04 ｜ **设计/实现状态**：草案 / 无

#### F-M17-01 资格判定与匹配度评分
- **优先级/阶段**：P0 / 阶段 2 ｜ **端**：S-MATCH ｜ **模块**：M17
- **用户故事**：作为用户，我想只看到真正适合我家的持证旅行社线路，并按合适程度排序。
- **验收标准**：
  1. Given 画像含海拔上限 3,000 米，When 匹配，Then 最高海拔超过 3,000 米的线路不出现在结果与“接近但不满足”分区中。
  2. Given 线路只在预算上超出 ≤ 15%，When 匹配，Then 进入“接近但不满足”分区并写明“比预算高 X%”。
  3. Given 同一画像、同一线路集合、同一规则版本，When 重复计算，Then 结果完全一致；规则版本号随结果保存。

#### F-M09-01 行程皮肤：按路线自动生成（免费一套；深度定制见 F-M12-03）
- **优先级/阶段**：P1 / 阶段 2 ｜ **端**：渲染引擎（行程页、路书阅读、分享卡片、单文件导出） ｜ **模块**：M09
- **用户故事**：作为领队，我想让 AI 给这趟行程做一份带着这条路线样子的路书（封面、配色），以便发到家庭群和朋友圈——全家看到的、分享出去的、导出保存的都有这趟旅行自己的样子。
- **验收标准**：
  1. Given 行程形成方案，When 首次生成分享版或打开行程页，Then 按途经地区与地点类别归类到主题族并按季节微调（置信度低时给两个候选，无法归类时用冰川银），结果写入行程 `theme`（`detection.mode = "auto"`），同步到全部成员的设备；免费用户与会员都有。
  2. Given 已设皮肤的行程，When 打开对话、旅行社线路的筛选与详情、咨询与报价、设置等页面，Then 外观不变；只有行程页、路书阅读、分享卡片、路线动画、导出与回忆录换皮肤。
  3. Given 生成的皮肤令牌，When 渲染，Then 正文对比度 ≥ 4.5:1（长辈模式 ≥ 7:1），不通过则回退到该主题族的安全底色；长辈模式、高对比或减少透明度开启时回到默认外观；警告、价格、匹配度与合规提示的颜色不随皮肤变化。
  4. Given 弱网或单文件导出，When 渲染皮肤，Then 纯 CSS 变量即时生效，封面与纹样为内联矢量图，无外部字体或图片依赖。
  5. Given 免费用户的分享页与导出，When 查看，Then 带自动生成的皮肤、「用 TripCraft 制作」角标与不可去除的 AI 生成标识；手动换主题、换版式、重新生成、去角标属会员（F-M12-03）；Given 会员到期，Then 已做的定制保留、不能再改。
  6. Given 旅行社交付的白标路书，When 查看或分享，Then 以旅行社品牌包为准，用户皮肤不覆盖，也不出现 TripCraft 角标与「我也做一份」入口；旅行社可在品牌色之内选用官方版式（B 端）。
- **依赖**：F-M08-02（分享链接）；F-M08-01（阶段 3 导出时内联皮肤） ｜ **设计/实现状态**：草案 / 无

#### F-M09-04 可分享的路线动画短视频（C 端）
- **优先级/阶段**：P1 / 阶段 3 ｜ **端**：C-MOBILE, C-WEB（在设备上渲染） ｜ **模块**：M09

#### F-M12-03 C 端会员：个性化服务与单趟解锁
- **优先级/阶段**：P1 / 阶段 3 ｜ **端**：C-MOBILE, C-WEB ｜ **模块**：M12
- **用户故事**：作为领队，我想为一次重要的出行（比如爸妈的结婚纪念旅行）做一份更有纪念意义的路书，以便分享和留念。
- **验收标准**：
  1. Given 免费用户，When 使用任何功能（对话、两条路径、共享同步、可分享的个性化路书、离线导出、车机投递、长辈模式、回忆录），Then 不出现付费墙；平台模型额度用完时提示改用自带 API 或开通会员，已形成的需求画像与行程不受影响。
  2. Given 会员，When 编辑可分享的路书，Then 可手动换主题与版式、配多套皮肤、重新生成，选择纪念日主题版式与扉页寄语，去掉或替换角标、自定义短链名、用自己的照片和文案做分享卡；路线动画可导出高清无角标（F-M09-04）；回忆录可生成按皮肤排版的画册与高清 PDF。
  3. Given 免费用户编辑分享路书，When 点到会员项，Then 先在这趟行程上看到预览，再决定是否开通（A-07）。
  4. Given 单趟解锁，When 购买，Then 只对这一趟行程生效，行程结束后定制保留（是否上线以 A-07 的验证为准）。
  5. Given 会员到期，When 查看已定制的行程，Then 定制保留、不能再改；之后新生成的分享与导出恢复角标；AI 生成标识任何时候都不能去掉。
- **依赖**：F-M09-01, F-M09-04, F-M10-03 ｜ **设计/实现状态**：草案 / 无

#### F-M12-04 成交服务费结算（以 D6 为前提）
- **优先级/阶段**：P2 / 阶段 3（D6 决定站内交易后才开发） ｜ **端**：C-CONSOLE, S-BILLING ｜ **模块**：M12
- **用户故事**：作为平台运营，我想在旅客经平台成交时向旅行社收取一笔公开的服务费，以便收入随成交增长，而旅客不需要为此多付钱。
- **验收标准**：
  1. Given 旅客经站内交易（D6）支付团款，When 分账，Then 通过持牌支付机构的分账服务，按合作协议的费率与上限扣除服务费，平台不设资金池（[docs/03 §3.7.1](../03-b2b-agency-operations.md#371--首要合规约束平台不经手游客资金)）。
  2. Given 服务费规则，When 旅行社签约与查看工作室，Then 费率、上限与逐单明细都可见；规则变更提前公示。
  3. Given 旅客看到的价格，When 报价与支付，Then 就是旅行社的报价，平台不另外加价，也不在旅客价格里藏费用。
  4. Given 匹配与排序，When 计算匹配度，Then 与服务费费率无关（ADR-010）。
  5. Given 疑似站外成交（咨询、报价后在站外签约），When 统计，Then 只用于评估 A-20 与调整计费方式，不以此处罚旅客（信号与对照设计见 [DLV-04 §3.5–§3.6](../delivery/DLV-04-metrics-and-data-collection.md#35-怎样发现站外成交与报价变化)）。
- **依赖**：F-M18-06 ｜ **设计/实现状态**：草案 / 无

#### F-M13-04 线路内容审核与上架准入
- **优先级/阶段**：P0 / 阶段 1 ｜ **端**：C-CONSOLE (Ops) ｜ **模块**：M13
- **用户故事**：作为平台合规人员，我想确保只有持证旅行社的、信息完整且如实的线路参与匹配。
- **验收标准**：
  1. Given 线路提交上架，When 所属机构资质未认证或已过期，Then 自动驳回。
  2. Given 线路进入审核，When 检查，Then 核对包含 / 不包含清单完整、素材标注实拍或示意、无 BR-015 违禁表述；驳回须写明原因。
  3. Given 在售线路被投诉信息不符，When 核实成立，Then 通知旅行社限期更正，逾期自动下架并保留审计记录。

#### F-M13-05 第一方统计与指标看板（不引入第三方统计）
- **优先级/阶段**：P0 / 阶段 2 ｜ **端**：S-OPS 后端, C-CONSOLE (Ops) ｜ **模块**：M13
- **用户故事**：作为业主与平台运营，我想从阶段 2 上线第一天起就看到分享获客与咨询成交的真实数据，以便验证 A-19、A-20 等假设；同时不让统计变成另一条收集个人信息的渠道。
- **验收标准**：
  1. Given 分享版（路书链接、分享卡片）与导出的单文件路书，When 构建产物，Then 不含统计代码、外部请求与任何访客标识，`telemetry` 保持关闭（[docs/04 §4.14](../04-dsl-specification-v1.md#414-telemetry--埋点默认全关)）；分享打开与「我也做一份」点击只在平台自建的短链与落地地址的服务端计数，不写 Cookie、不做设备指纹。
  2. Given 访客从分享页点「我也做一份」并注册，When 记录来源，Then 新账号上只记渠道、分享版生成周与分享者档位，不记分享者身份，也不存分享令牌；用户在设置里关闭来源统计后，这些字段被清除。
  3. Given 看板与导出的统计表，When 查询，Then 只有汇总，少于 10 的格子显示「<10」；统计数据不含姓名、联系方式、证件、行程地点与日期、同行人构成与健康信息。
  4. Given 旅客接受报价 14 天后，When 平台询问是否成交，Then 旅客可以跳过；答案不提供给旅行社，不影响旅客的账号、匹配结果与咨询。
  5. Given 疑似站外成交或报价变化的信号，When 统计，Then 只做汇总评估（A-20），不进入匹配度（ADR-010），不处罚旅客，不自动处罚旅行社。
  6. Given 统计数据到达保存期限，When 定时任务运行，Then 按 [DLV-04 §4.3](../delivery/DLV-04-metrics-and-data-collection.md#43-保存多久) 删除或并成汇总，并留删除日志。
  7. Given 指标口径或过滤规则变更，When 发布，Then 记录口径版本与生效日期，看板标出变化点。
- **依赖**：F-M08-02, F-M18-06, F-M01-01 ｜ **设计/实现状态**：草案 / 无

## 4. 横切需求与约束 (Cross-Cutting Requirements)

1. **离线可用性**：已同步到设备的行程与已导出的单文件 HTML，必须满足断网无白屏可用（[docs/00 铁律 3](../00-overview-and-glossary.md#铁律-3--降级不可耻白屏才是罪-degrade-never-blank)）。
2. **细粒度权限控制**：机构客户与长辈默认只读；随团司导仅具有路况报备与脱敏名单查阅权；机构管理员掌握财务与席位。
3. **无障碍设计 (A11y)**：提供长辈大字关怀模式（字号 ≥ 18px，触控区域 ≥ 48px，WCAG 2.1 AA 级对比度）；筛选页滑块与方块支持键盘与读屏（[docs/16 §16.7.8](../16-planning-paths-and-route-matching.md#1678-无障碍)）。
4. **国际化支持**：现阶段严格聚焦中国大陆市场及境内合规地图（GCJ-02），多语言与境外离线地图**暂不做**，标为远期演进项。
5. **模型无关的质量底线**：无论使用平台模型还是自带模型，需求画像与行程草案写入前都必须通过服务端校验（[ADR-009](../architecture/adr/ADR-009-llm-provider-byok.md)）。
6. **匹配的公正性**：付费推广不进入匹配度计算；匹配结果可复现、可分项解释（[ADR-010](../architecture/adr/ADR-010-route-matching-scoring.md)）。
7. **个人信息向旅行社提供**：仅在旅客发起咨询并确认发送范围后发生（[docs/16 §16.8](../16-planning-paths-and-route-matching.md#168-线路详情与按需调整)）。
8. **统计不越过隐私边界**：只用第一方统计，不引入第三方统计 SDK；分享页与导出文件不含统计代码；统计只出汇总；疑似站外成交等信号不处罚旅客、不进匹配度（F-M13-05、[DLV-04](../delivery/DLV-04-metrics-and-data-collection.md)）。
