## 1. 官网定位、目标受众与核心使命

### 1.1 官网定位界定
本项目**不是**繁重的企业级后台管理系统或单纯的业务操作端，而是 **TripCraft 品牌与能力的超级展示窗口（Interactive Showcase & Living Exhibition）**。其视觉与交互标准对标 Apple 产品发布页、Linear.app 与 Stripe Press，兼具学术严谨性与消费级美学。

### 1.2 四大目标受众与诉求匹配
```mermaid
flowchart TD
    VISITOR["官网访客矩阵"] --> C["C 端自驾游客 / 家庭领队<br/>感受 AI 懂人性的温度、适老适幼排程与好看实用的路书"]
    VISITOR --> B["B 端定制机构 / 地接社<br/>看重机构品牌白标、考斯特通达性规则与高效出单"]
    VISITOR --> OEM["车企座舱与生态伙伴<br/>关注 Tier 0 极简投车协议、HUD 镜像与零依赖交付"]
    VISITOR --> DEV["开发者 / 投资人 / 评委<br/>审视 Local-First 离线架构、DSL 契约与单文件编译器硬实力"]
```

### 1.3 核心设计铁律
1. **无需登录，开箱即秀**：全站所有功能展示与动画演示 100% 免登开放，访客只需滑动滚轮即可体验全部核心价值。
2. **滚动即叙事 (Scrollytelling First)**：将抽象的“输入-AI推演-排程-协作-算路”复杂业务流，转化为一气呵成的视差滚动电影级长镜头。
3. **真实感与可信度**：演示中的路书、地图经纬度、高程起伏与考斯特车型限制，全部基于真实的甘青大环线 9 天（Dunhuang Silk Road 9D）工程数据。

## 4. 核心演示区规格（两段独立的场景动画）

> 本版块是展示官网的灵魂所在。演示区由两段**互相独立**的舞台组成：C 端舞台（`ScrollyStage`，锚点 `#demo`）只讲旅客从对话到全家同步的完整使用流，中间不插入旅行社端内容；B 端舞台（`AgencyStage`，锚点 `#agency`，挂在 C 端舞台之后）以旅行社定制师的视角讲同一天。两段各有自己的章节导航、进度与节奏，但讲的是**同一家人、同一条线路**。

### 4.0 幕间衔接与数据贯穿（2026-10-20）

**规则**：每一幕以一次演示光标的点击结束，下一幕开头就是这次点击的结果；切换通过点击视窗里真实的按钮或导航完成，不硬切。

| 衔接 | 上一幕最后一下 | 下一幕开头 |
| :--- | :--- | :--- |
| C 01 → 02 | 需求画像底部点「AI 规划自驾路线」（按钮转为「正在规划自驾路线…」） | 自驾草案，路线开始描绘 |
| C 02 → 03 | 草案「保存到行程空间」（提示「已保存到行程空间「西行计划」」）；结果页底部提示「同一份需求画像，也匹配到 23 条旅行社线路 · 其中 5 条与这份自驾草案相似」，点「看旅行社线路」 | 筛选页标题下的画像胶囊条「**已套用需求画像** · 5 人 · 1 长者 1 儿童 · 国庆前后 · 8–10 天」；分布图已在，画像里的预算与天数随后着色，来自画像的方块依次选中并带 ★ |

**时钟**：每个舞台一只 rAF 时钟驱动一条全局进度 MotionValue，场景经 `ProgressContext` 读取，播放过程 0 React 重渲染。

- **播放速率**：时间轴按「时间轴秒」书写（`ACT_ORDER` / `AGENCY_ORDER` 的时长与关键帧），时钟每帧推进 `dt × PLAYBACK_RATE`。2026-10-21 起 `PLAYBACK_RATE = 0.9`：C 端 68 → 约 76 秒（2026-10-23 第 4 幕由 18 秒加到 20 秒，原为 66 → 约 73 秒），B 端 61 → 约 68 秒；调整整体节奏只改这一个常量。
- 章节区间按时长比例首尾相接（前一章的终点就是后一章的起点），自动播放跨章时进度连续，没有空档或跳帧；「一秒」在任何一章都对应同样的进度跨度。
- **只播放一遍**：最后一章结束后停在终帧，按钮变为「重新播放」。
- 视窗露出不足 35% 时挂起；时钟累加每帧耗时（单帧最多计 64ms），切走标签页或掉帧回来不会跳章。两段舞台同在一页，只有可见的那段在跑。
- 手动点选章节时落在该章画面已完全淡入的时刻（`enter`），不会闪过上一章的画面。

**换章时版面不动**（2026-10-20 修复）：旧版换章时当前章说明直接卸载、新章说明从 0 高度展开，垂直居中的左栏先缩短约 35px 再长回来；浏览器的滚动锚定随之替访客滚动页面，实测每次换章整页上移约 37px，到第 4 幕视窗顶部已滑到导航条下面。现在左栏顶端对齐，所有章的说明都渲染、用 `grid-template-rows: 0fr ↔ 1fr` 同时收放（0.3s `cubic-bezier(0.2,0.8,0.2,1)`）；手机上当前章说明占固定高度（最多 3 行）。实时播放复测：换章前后页面滚动位置、左栏位置与高度均不变。

   - *头像与状态*：同行人头像依次入列；设备同步逐行变为 v1.1；咨询的成交进度用五个点表示（咨询 → 报价 → 接受 → 成交 → 交付）。

6. **字号与网格**：正文 13px，页面标题 15px，辅助文字不小于 12px（`text-xs`），任何文字不低于 12px；数字用等宽数字（`tabular-nums`）。控件高 32px（主操作 40px），间距取 4 / 8 / 12 / 16 / 24px。
7. **动效只说明当前这一步**：演示光标移到控件上按下 → 结果出现；同一时刻不让多个元素同时闪动；透明度为 0 的元素同时 `visibility: hidden`（`useFadeVisibility` / `useFadeStyle`），iPad Safari 才不会留下上一帧的残影。
8. **状态栏**只写对这一步有意义的信息（数据来源、合规口径、同步状态）。

**按视窗自身宽度排版**：桌面双栏时视窗只占右侧一栏，堆叠时又占满整行，视口断点反映不了视窗的真实宽度。视窗根节点声明 `container-name: win`，子元素用 Tailwind 插件注册的 `cq-sm`（≥ 560px：标题栏、图标侧栏、状态栏）、`cq-md`（≥ 680px：上下文面板、左右分栏）、`cq-lg`（≥ 800px：侧栏文字与附加区）变体排版（见 `tailwind.config.ts`）。桌面左栏 300–340px，视窗约 840px（`cq-lg`）；iPad 横屏 1180 / 1194px 时视窗约 760px（`cq-md`），1024px 时约 600px（`cq-sm`）。手机宽度（375px）下视窗是一款手机 App：底部标签栏，上下文面板改为底部抽屉。

**文案口径**：涉及匹配与报价的界面文字遵守 [docs/00 §0.3](00-overview-and-glossary.md#03-三条责任边界线tripcraft-不是清单) 末尾的正确表述——匹配度为信息参考、预估价以旅行社正式报价为准、合同与付款由旅客与旅行社直接签订；平台不自称旅行社，也不出现「立即预订」「平台担保」一类表述。

### 4.4 减弱动态效果与降级

- `prefers-reduced-motion: reduce`：两段舞台都**不自动播放**，每章停在一张能说明结果的静帧，访客点选章节或「上一章 / 下一章」切换，也可以手动播放；位移类动画降级为纯淡入，CSS 循环动画关闭。C 端 04 幕的静帧是亲友刚打开分享页的一刻：换上皮肤的分享卡片、角标与「AI 生成」标识、「我也做一份」都在画面里，手机宽度也看得到皮肤。
- 地图是示意矢量底图（近似经纬度手绘，标「示意底图 · 非图商数据」），不依赖外部地图服务；视窗内全部为本地组件，没有运行时拉取的素材。
- 地图浮层的玻璃材质在不支持 `backdrop-filter` 或系统要求减少透明度时退回实色。
- 只靠透明度隐藏的元素在透明度为 0 时同时 `visibility: hidden`，避免 iPad Safari 留下上一帧的残影（2026-10-21：需求画像空状态曾出现「少山日落」「8–10 天」的残影）。

> 车机座舱（`CockpitScene.tsx`）、离线交付（`Deliver.tsx`）与旧版倾诉幕（`ChatScene.tsx`）已不挂载，文件暂未删除；`timeline.ts` 为它们保留的键落在全局进度 2 以后，进度到不了。

## 6. 展示官网前端技术栈与开发架构

### 6.1 前端技术栈选型
1. **应用框架**：`Next.js 16+`（App Router，Webpack 静态打包，纯静态生成 SSG `output: 'export'`，部署在 GitHub Pages）。
2. **UI 库与运行时**：`React 19` + `TypeScript 5`。
3. **样式引擎**：`Tailwind CSS v3.4+` + 原生 CSS 变量注入（Unify GTM 设计系统令牌）。
4. **滚动视差引擎**：
   - `Framer Motion v12+`：全舞台采用纯 `MotionValue` 驱动，0 React 重渲染调度，消除了卡顿与动画抢播；
   - 复杂矢量路径与高程剖面采用 SVG 动态插值。
5. **地图**：
   - 演示站不接地图引擎与瓦片服务：视窗里的地图是 `MapCanvas` 用 SVG 画的示意矢量底图（`data/basemap.ts`，近似经纬度手绘），路线按弧长描绘、地名用 HTML 叠加，标「示意底图 · 非图商数据」。产品里的真实底图与算路走持牌图商（PRD-01 §5、BR-025），不在演示站范围。

- 关键帧一律以全局进度存放在各自时间轴的 `T`（C 端）/ `AT`（B 端），按章内比例书写（`actAt(id, t)`），时长用 `sec(秒)`；调整某章节奏只改该章时长与对应关键帧。

- 视觉巡检：`window.__setStageProgress(v)` / `window.__setAgencyProgress(v)` 跳到任意全局进度并暂停。

### 6.3 无障碍与多端性能兜底策略
1. **减弱动态效果媒体查询 (`prefers-reduced-motion: reduce`)**：
   - 两段舞台都不自动播放，每章停在一张能说明结果的静帧，由访客点选章节或手动播放；位移与缩放在 JS 层降级为纯淡入（`useRange` 的 `rest`），CSS 循环动画关闭。
2. **移动端纵向优化 (Mobile Fallback)**：
   - 屏幕宽度 `< 1024px` 时舞台上下堆叠，章节导航改为紧贴视窗上方的横排进度条与当前章说明；视窗按自身宽度切换为手机 App 布局（底部标签栏，上下文面板改为底部抽屉）。
3. **老旧设备与弱 GPU 降级**：
   - 检测 FPS 低于 45 时，自动剥离毛玻璃多层高斯模糊（`backdrop-filter`），回退至高对比度半透明实色，确保任意设备秒开 60fps。
4. **网络字体不阻塞渲染**：
   - Google Fonts 样式表不再写在 `<head>` 里（连不上时整页白屏到请求超时），改由 `FontLoader` 挂载后插入；先用系统字体渲染，加载失败只记一条警告。
5. **换章不触发滚动锚定**：
   - 舞台换章时版面高度保持不变（§4.1），浏览器的滚动锚定不会替访客滚动页面。
6. **iPad 与 WebKit**：
   - 只靠透明度隐藏的元素，透明度为 0 时同时 `visibility: hidden`（`useFadeVisibility` / `useFadeStyle`），iPad Safari 不会留下上一帧的残影；
   - 横屏 1024–1279px 时左栏 300px，播放控制用图标按钮，整行不折行；巡检加入 1024 / 1180 / 1194 三种宽度。
7. **地图浮层的玻璃**：不支持 `backdrop-filter` 或 `prefers-reduced-transparency: reduce` 时退回实色。
