# ADR-010 旅行社线路匹配评分机制

- **status**: Proposed
- **date**: 2026-10-17
- **背景与约束**：
  产品基线 v3 的路径 B 要求"根据用户的需求自动匹配旅行社路线，显示匹配度百分比"，并在筛选页上用价格、天数滑块与条件方块调节（[PRD-01 §2](../../product/PRD-01-vision-positioning.md#2-核心使用流程)、[docs/16 §16.6](../../16-planning-paths-and-route-matching.md#166-路径-b--旅行社线路匹配)）。约束：
  1. 匹配度是展示给用户的数字，必须**可解释**（能拆成维度分项）；
  2. 必须**可复现**（同一画像、同一线路集合得到同一结果），以便处理旅行社与用户的申诉；
  3. **付费不能影响匹配度**；
  4. 冷启动期线路少（几十到几百条），没有足够的行为数据训练模型。

- **选项对比**：
  - **选项 A：两段式规则评分（资格硬过滤 + 维度加权打分）**
    - *优点*：每个分数可拆解解释；确定性、可复现；不需要训练数据；权重可由产品调整并公开。
    - *代价*：维度和权重需要人工设计与校准；对"说不清的偏好"表达力有限。
    - *风险*：权重设得不好时匹配度"说不准"——由校准指标监控（A-15）。
  - **选项 B：向量语义检索（画像与线路描述做 embedding，按相似度排序）**
    - *优点*：能捕捉模糊语义；实现快。
    - *代价*：相似度不可拆解解释；硬约束（海拔、容量）无法保证；模型更换后结果整体漂移。
    - *风险*：给有海拔禁忌的长辈推荐高原线路，只因为文字描述"很像"。
  - **选项 C：学习排序模型（LTR）**
    - *优点*：数据充足后效果最好。
    - *代价*：冷启动期没有训练数据；可解释性差。

- **评估标准**：身体安全相关硬约束必须保证（一票否决）、可解释性、可复现性、冷启动可用性。

- **建议决策 (Proposed)**：
  **采纳选项 A；选项 B 仅作为"主题偏好"维度内的辅助信号；选项 C 在积累足够咨询与成交数据后重新评估。**
  1. **资格判定**（不满足即不展示）：资质有效、线路在售、不含回避项、满足身体约束、容量足够、团期可用。**可放宽项**（预算超出 ≤ 15%、天数 ±1、团期偏离 ≤ 7 天）只差一项时进入"接近但不满足"分区。
  2. **维度评分**：每个维度输出 `[0,1]` 分值与一句理由；默认权重：目的地覆盖 25%、预算贴合 20%、天数与日期 15%、节奏与体力 15%、人群适配 10%、主题偏好 10%、住宿与服务 5%。
  3. **缺失维度**：线路未提供某维度信息时，该维度标"未提供"并从加权中移除，其余权重归一。
  4. **权重调整**：用户在对话中强调的维度或在「我更看重」中选择的维度（最多 2 个）各 +10 个百分点，其余等比缩减。
  5. **展示**：`round(score × 100)`，上限 99；默认阈值 60。
  6. **隔离**：旅行社评分、推广付费、完整度均**不进入**匹配度计算；推广位单独标注"广告"。
  7. **可复现**：评分函数为纯函数 `score(profile, listing, weights, rulesVersion)`；规则版本号随结果保存。

- **影响**：
  - 新增后端逻辑模块 `S-MATCH`（[ARC-05](../ARC-05-backend-integrations.md)）；筛选页的分面计数与分布图数据由 `S-MATCH` 提供。
  - 需求画像与上架信封需要数据契约（OI-024）——已落地为 [`profile.schema.json`](../../../spec/profile.schema.json) 与 [`listing.schema.json`](../../../spec/listing.schema.json)。
  - 匹配度校准成为常规运营指标：按匹配度分段统计咨询率，检验是否单调（A-15）。

- **重新评估的触发条件**：
  累计咨询记录超过数千条且匹配度校准持续不单调时，评估引入学习排序；或主管部门对算法推荐提出备案、公示等新要求时（OI-021）。
