# ADR-006 离线快照作为一等交付格式

- **status**: Proposed
- **date**: 2026-10-08
- **背景与约束**：
  长辈不会装复杂 App、无人区无移动信号、地接社需要带企业白标一键秒发微信客户（关联 [PRD-01](../../product/PRD-01-vision-positioning.md)、[docs/15 §15.2](../../15-multi-device-and-collaboration.md#152-破除假想的四堵墙多端-app-如何兼顾全场景与-b-端白标)）。需要确立交付格式的技术形态。

- **选项对比**：
  - **选项 A：零外部依赖自包含单文件 HTML (Single-File Autonomous HTML)**
    - *优点*：单一 `.html` 文件，内联 CSS Token、JS 运行时与 DSL 数据；微信点开秒看，无需登录、无需下载安装；断网飞行模式双击即开；可长久保存数年不变质；对 B 端地接社而言具备极高数字化仪式感。
    - *代价*：编译器需处理静态资源内联（Base64/内联脚本）；限制产物总大小需控制在 ≤ 2MB。
    - *风险*：若排版复杂度过高可能增加首屏内联解析开销。
  - **选项 B：传统静态多文件打包 (HTML + 外部 CSS/JS 资源包)**
    - *优点*：现代 Webpack/Vite 默认产物形态。
    - *代价*：在微信中以文件转发给长辈时，长辈下载到本地会发生相对路径资源引用丢失，导致白屏或样式混乱；无法做到真正意义上的“单文件分享即交付”。
    - *风险*：极易触发“降级白屏”铁律红线。
  - **选项 C：纯 PDF 电子文档**
    - *优点*：极其普及，打印方便。
    - *代价*：纯静态死死排版，无法进行时间轴折叠、无法点击一键拨号呼叫管家、无法一键调起座舱导航、无法自适应手机与平板排版。
    - *风险*：退化为平庸的纸质替代品，失去交互路书核心价值。

- **评估标准**：免安装使用门槛（对长辈与客户友好度）、断网完全自愈性、交互能力（拨号与导航深链唤起）。

- **建议决策 (Proposed)**：
  **采纳选项 A**。将 **零外部依赖单文件 HTML 作为一等公民交付形态 (First-Class Artifact)**。
  以 `C-SNAPSHOT` 为标准运行时；兼顾可选的 PDF 打印导出（选项 C）作为纯物理备份，但系统数字交付的主体为自包含单文件 HTML。

- **影响**：
  必须保障编译流水线（`S-EXPORT`）具备严苛的内联打包与压缩能力；确立了产品的核心护城河交付体验。

- **重新评估的触发条件**：
  主流移动端系统对本地单文件 HTML 的打开支持出现重大安全策略限制阻碍时重新评估。
