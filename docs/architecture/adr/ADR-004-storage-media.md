# ADR-004 主存储与媒体存储架构选择

- **status**: Proposed
- **date**: 2026-10-08
- **背景与约束**：
  系统需要管理结构化租户与行程元数据、高频演进的 JSON DSL 文档树，以及单文件离线 HTML 产物、照片足迹等媒体文件。关联实体参见 [ARC-02 领域模型](../ARC-02-domain-data-model.md)。

- **选项对比**：
  - **选项 A：PostgreSQL (关系模型 + JSONB) + 兼容 S3 的对象存储 (OSS/S3)**
    - *优点*：PostgreSQL 的 `JSONB` 能原生高效存储与索引 Trip DSL 树结构；同时具备成熟的 ACID 关系事务与行级安全 (RLS)；S3/OSS 提供近乎无限扩展、高可靠且低成本的快照与图片托管；标准生态完善。
    - *代价*：需要维护关系数据库的常规备份与连接池配置。
    - *风险*：若开发人员滥用 JSONB 导致无结构膨胀，需通过 Schema 校验严守入库契约。
  - **选项 B：纯文档数据库 (MongoDB) + 网格文件系统 (GridFS)**
    - *优点*：全 JSON 存储，前期开发灵活。
    - *代价*：多租户权限校验与跨表财务审计的事务一致性保障偏弱；GridFS 托管静态网页的 CDN 缓存生态不如标准 S3 对象存储成熟。
    - *风险*：数据关系失控与版本迁移困难。

- **评估标准**：结构化数据与 JSON 混合查询能力、多租户行级安全成熟度、媒体托管与 CDN 边缘加速便利性。

- **建议决策 (Proposed)**：
  **采纳选项 A**。采用 **PostgreSQL (JSONB) 作为主业务数据库 + S3 兼容对象存储作为媒体与单文件快照宿主**。
  业务表管理租户、角色、订单与行程基本元数据；`trip_json` 以 `JSONB` 字段存储并由 `spec/trip.schema.json` 强校验；编译产出的静态 HTML 直传对象存储并由边缘 CDN 加速。

- **影响**：
  架构清晰分层；静态产物与中心业务数据库在物理网络和安全边界上完全解耦。

- **重新评估的触发条件**：
  若未来行程文档历史版本累积导致单库容量达到 TB 级，可考虑将冷备历史版本单独卸载至只读数据湖。
