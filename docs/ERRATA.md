# TripCraft 历史勘误与外部事实核查记录 (Errata & Corrections)

本文件归档 TripCraft 在架构演进与外部事实核查过程中的勘误声明、能力边界纠偏与初稿对照表。

---

## 外部事实核查与更正声明

本文档中的技术能力表述以执行全书（[docs/README.md](README.md)）为准。
执行全书在 2026-10-07 与 2026-10-08 开展了两轮外部事实核查，修正了初稿若干处超出实际能力的说法（主要是智能座舱交付中 NOA 领航辅助与车辆状态读取相关表述），并将商业断言与未验证假设解耦。

## 2.4 智能座舱交付能力边界更正

> ⚠️ **2026-10-07 更正说明**：本节初稿的标题与两处正文存在**技术事实错误**，已在第 2 章核查后修正。这不是措辞问题，而是如果我们按初稿去和车厂谈，第一个技术问题就会被问倒。

| 初稿说法 | 核查后的实际 | 详见 |
| :--- | :--- | :--- |
| 「一键注入车机底层导航…**直接激活**高速/城市领航辅助驾驶（NOA）」 | **没有任何车厂提供第三方导航注入 API。** NOA 是车厂自己的功能，Web 应用**无法触发**它 | [§2.1](02-cockpit-protocol.md#21-先做一次必要的纠偏) |
| 「**接入**车辆实时电量（SOC）」 | 我们**读不到**车辆状态。且一旦声称能读，就隐含了安全承诺 | [§2.6](02-cockpit-protocol.md#26-关于读取车辆状态必须明确说不) |

**修正后的定位**：愿景不变，但把可验证的部分和待验证的部分分开了：
1. **全天路线批量下发**：通过深链投递至车机高德/百度，由车机自行引导；
2. **手车互联**：依赖高德云端账号同步，零开发路径，但须实车验证定制版高德是否裁切；
3. **多屏自适应**：同一产物适配不同屏幕尺寸，不跨屏控制；
4. **电耗估算**：纯离线模型估算，明确提示用户以车显为准。

## 5.7 智能座舱与全天路线下发更正

> ⚠️ **2026-10-07 更正提示**：初稿有三处超出实际能力的表述（NOA 直发、多屏协同控制、车辆 SOC 接入）。

- **我们做得到的部分**：全天节点批量投递至车机导航、手车互联（高德账号同步）、多屏尺寸自适应、断网离线骨架图与文字路线自愈。
- **我们不做，也做不到的部分**：触发 NOA 领航辅助、控制车机多屏交互、读取车辆实时 SOC。
- 详细论证与车厂合作阶梯见 [第 2 章 · 座舱协议](02-cockpit-protocol.md) 与 [第 12 章 · 车厂合作](12-oem-partnership-design.md)。

## 视觉主题与流派的定位更正（2026-10-22）

> ⚠️ **2026-10-22 更正说明**：这不是外部事实错误，而是**产品口径在多轮编写中被混淆**。业主原意：按路线生成不同的皮肤，是用户开通会员后的增值功能。来源是白皮书：当时产品就是一份路书网页，§4.1「目的地语义嗅探器」换装的是**这份路书**；§5.2 写明普通版自动推荐单套适配色系、VIP 版提供「跨平台、多设计流派的自由换肤引擎」。产品改为多端 App（PRD-01 v3）后，后续文档把「给路书换装」写成了「给整个 App 换主题」，并且对所有人默认生效。

| 混淆后的写法 | 更正后的口径 | 详见 |
| :--- | :--- | :--- |
| 目的地语义嗅探自动给**整个 App** 换主题；免费版也自动匹配，「不阉割色彩」（docs/09 旧 §9.1.4） | App 外观统一（暖白 · 品牌橙，玻璃只用于叠在地图上的浮层），不随目的地变化；按路线生成的皮肤只作用于行程页、路书阅读、分享卡片、导出与回忆录：AI 自动生成的一套所有人免费，深度定制属会员 | [docs/09 §9.0](09-visual-design-system.md#90-两层app-外观与行程皮肤) |
| ARC-10 §5.1「默认主题：敦煌金」、经纬度逆编码自动切换 `[data-theme]`；§6.9 F-M09-01 按省份自动激活主题（P0） | 两层令牌：App 外观令牌全局统一；行程皮肤挂在 `.trip-surface[data-trip-theme]` 上，缺省回落到 App 外观；F-M09-01 改为「行程皮肤：按路线自动生成」（P1） | [ARC-10 §5.1](architecture/ARC-10-web-system-design.md#51-两层设计令牌app-外观与行程皮肤) |
| 流派注入 `<html data-genre>`，换的是整个产品的形态 | 「流派」改称「版式」，只挂在行程内容根节点；对外用中性名称（默认、流光、手账、极简、夜航） | [ARC-10 §5.2](architecture/ARC-10-web-system-design.md#52-版式原流派与兼容性拦截) |
| DSL `theme` 「缺省时由目的地语义嗅探自动决定」 | 方案形成后由 AI 自动生成一套（`detection.mode = "auto"`），会员手动定制为 `manual`；还没生成时用默认外观 | [docs/04 §4.6](04-dsl-specification-v1.md#46-theme--视觉主题) |
| 产品 UI 视觉体系二选一（docs/09 五主题 + 液态玻璃 / Unify GTM 暖纸）待决（D10） | 已定：采用演示站视窗的统一外观（丙）；Unify GTM 只约束演示站营销页面 | [PRD-01 §9](product/PRD-01-vision-positioning.md#9-待业主确认的决策) |
| 白皮书 §5.2 普通版「自动推荐单套适配的液态玻璃色系」 | 与最终口径一致（作用对象是行程而不是 App）：AI 按路线自动生成的一套皮肤所有人免费，用来做可分享的个性化路书；手动定制、更多版式、去角标等属会员（PRD-01 D9） | [docs/09 §9.0.3](09-visual-design-system.md#903-免费与会员) |
| 白皮书 §4.3「AI 文生图意境背景」 | 不用写实的 AI 景点图；封面用路线形状与原创抽象纹样 | [docs/09 §9.0.5](09-visual-design-system.md#905-护栏) |

**没有改的**：DSL 的 `themeId` / `designSystem` 枚举与 `meta.tier`（`spec/trip.schema.json`）、docs/09 §9.1–§9.3 的主题与流派设计本身——它们现在是行程皮肤的设计依据。

**同日后续定调**：业主确定「免费版使用全部功能、会员提供更多个性化服务」，并把用 AI 做可分享、可定制的个性化路书定为传播与获客入口，因此自动生成的一套皮肤改为所有人免费，会员提供深度定制（PRD-01 D9）。上表「更正后的口径」已按最终口径填写。
