# 第 10 章 · 路书产物的形态与阅读设计

> **本章性质**：产物设计与阅读体验规格，**不涉及技术实现**。
> **回答的问题**：用户最终拿到的那份东西，长什么样？怎么读？
> **为什么单列一章**：全书到此为止，**没有任何一章描述过产物本身**。这是一个明显的空洞——所有交互、所有视觉、所有数据，最终都收束到这一个东西上，但它从未被设计过。
> **⚠️ 本章只设计三层中的一层（2026-10-08 注）**：本章管的是**交付层**——行中真正被读的那份路书。它上游的**协作层**（一群人怎么共同产出它）与下游的**分享层**，见 [第 15 章](15-multi-device-and-collaboration.md)。**别把本章的产物当成整个产品。**
> **状态**：`Design Spec`

---

## 10.1 设计立场：路书不是行程表

### 10.1.1 行程表与路书的分野

| | 行程表 | **路书** |
| :--- | :--- | :--- |
| 本质 | 一列**数据** | 一天的**剧本** |
| 回答 | 「几点到哪」 | 「今天是什么样的一天」 |
| 读法 | 查 | 读 |
| 出问题时 | 无话可说 | 有 Plan B |
| 旅途中 | 越用越没用 | 越用越有感情 |

> 📌 **这个分野决定了整章的设计。**
>
> 行程表是**给人查的**，所以它只需要准确；路书是**给人读的**，所以它需要有**叙事**。
>
> **一份只有准确信息的行程表，在出发第二天就会被扔掉**——因为用户已经知道今天去哪了，他不需要再查一遍。
>
> **而路书要在第二天早上仍然有用**，所以它必须提供**行程表给不了的东西**：今天是什么调性、哪里有坑、出事了怎么办、以及——**为什么这个点值得停**。

### 10.1.2 三条产物原则

| # | 原则 | 含义 |
| :--- | :--- | :--- |
| **A1** | **一天的调性在第一天就知道** | 用户扫一眼标题就知道今天该有什么心理准备 |
| **A2** | **五层信息同时存在，按需取用** | 不想读的人一秒扫过，想读的人能读五分钟 |
| **A3** | **没有信号的时候它必须还能用** | 隧道、无人区、山区——这恰恰是最需要它的时候 |

## 10.2 ★ 一天的性格标签

### 10.2.1 为什么需要它

**用户是按「天」来规划旅行的，不是按「景点」。**

他早上醒来想的不是「今天要去玉门关」，而是「**今天是不是很累的一天**」。

**但现有的所有行程表都只告诉用户"去哪"，不告诉他"今天会是什么样"。**

### 10.2.2 六种日型

| 日型 | 特征 | 标题区呈现 | 视觉处理 |
| :--- | :--- | :--- | :--- |
| 🚗 **赶路日** | 里程长、停留点少 | 「今天主要是赶路」 | **紧凑**——时间轴压缩，不铺垫 |
| ⭐ **精华日** | 有全程核心景点 | 「今天是最值得的一天」 | **重**——图片放大，正文展开 |
| 🦥 **轻松日** | 里程短、可晚起 | 「今天可以睡到自然醒」 | **松**——留白多 |
| ⛰️ **挑战日** | 海拔跃升 / 路况差 / 强度高 | 「今天海拔上得快，注意身体」 | **警示**——带醒目标记 |
| 🏕️ **休整日** | 原地停留，不移动 | 「今天不动，休整」 | **平**——信息最少 |
| 🛟 **缓冲日** | 无固定安排 | 「今天没安排，留给意外」 | **空**——明确说明用途 |

> 🔴 **「🛟 缓冲日」是本设计里最反常识的一项，也是最重要的一项。**
>
> 多数行程表会**把每一天填满**——因为空隙看起来像浪费。
>
> **但真实的旅行一定会出意外**：孩子在鸣沙山玩到不肯走、轮胎破了、有人高反了、下雨了拍不了照。**这些意外没有地方消化，就变成了赶路和吵架。**
>
> **缓冲日不是"空着一天"，而是"把意外提前安排在计划里"。** 它是唯一一个**没有安排也不算失败**的日子——**而这正是它的全部价值。**

### 10.2.3 标题区的完整设计

```text
╔═══════════════════════════════════════════════════════════╗
║  D3                                        ⭐ 精华日        ║
║                                                           ║
║  敦煌 → 大柴旦                                             ║
║                                                           ║
║  ┌─────────┬─────────┬─────────┬──────────┐               ║
║  │  320km  │  4.5h   │  ↑1860m │  2 个停留 │               ║
║  │  里程   │ 行车时长 │ 海拔变化 │  值得去的 │               ║
║  └─────────┴─────────┴─────────┴──────────┘               ║
║                                                           ║
║  「今天有一段路风很大，但值得」                             ║
╚═══════════════════════════════════════════════════════════╝
```

**设计要点**：

| 元素 | 为什么 |
| :--- | :--- |
| **日型标签在右上角** | 一眼扫过就能定位今天的调性 |
| **四个数字，不是六个** | 里程/时长/海拔/停留数——**再多的数字就没人看了** |
| **海拔变化带方向箭头** | 「↑1860m」比「1860m」信息量大十倍——**上升是警告，下降是轻松** |
| **一句话在最后** | 它是**总结**，不是**预告**——放最后才读得到 |

> ⚠️ **「四个数字，不是六个」这条要守住。**
>
> 数据面板的常见病是**把能算出来的都摆上**：总里程、行车时长、游览时长、海拔、爬升、油耗、过路费……
>
> **但数字超过四个，就变成了背景噪音——用户会全部跳过。**
>
> **四个是"每一条都会被读"的上限。** 其余数字**不是删掉，是下沉到第二层**（展开后可见）。

## 10.3 ★ 五层信息深度

### 10.3.1 层级的定义

一份路书必须同时服务两种人：**想扫一眼就走的人**和**想读透的人**。

**解法不是做两个版本，而是做五个深度层，折叠在同一个产物里。**

| 层 | 内容 | 用户投入 | 默认状态 |
| :--- | :--- | :--- | :--- |
| **L1 一眼** | 日期 · 路线 · 四个数字 · 日型 | **1 秒** | 收起 |
| **L2 扫读** | 时间轴节点名 + 时间 | **10 秒** | **展开** |
| **L3 细读** | 每个点的时长、门票、要不要预约 | **1 分钟** | 收起 |
| **L4 深读** | 攻略、典故、拍照机位、避坑 | **5 分钟** | 收起 |
| **L5 备用** | 应急电话、备选路线、加油站 | **出事时** | 收起 |

> 📌 **L2 默认展开、其余收起** —— 这个默认值是刻意选的。
>
> **默认展开 L2 是因为它回答最多数人的问题**：「今天要去几个地方？」
> **L1 收起是因为它已经在标题区了**（§10.2.3），不需要重复。
> **L3 收起是因为它只在"要去了"的时候才需要**。
>
> **默认状态不是"全展开更友好"，而是"用户现在最想知道什么"。**

### 10.3.2 五层如何在版面上共存

**用折叠，不用分页。**

```text
D3 · 敦煌 → 大柴旦                        ⭐ 精华日
320km · 4.5h · ↑1860m · 2 个停留

├─ 08:00  ● 出发 · 敦煌市区
│          └─ 出城前加满油（最后一个便宜加油站）
│
├─ 09:40  ○ 玉门关遗址                    ▸
│            40 分钟 · 门票 ¥40
│
│         ┌─ 展开后 ───────────────────────────┐
│         │ 「羌笛何须怨杨柳，春风不度玉门关」   │
│         │ 这个土墩就是诗里的玉门关。            │
│         │                                      │
│         │ 📷 机位：站在南侧 50m 拍全景，        │
│         │    下午光太硬，上午来正好             │
│         │ ⏱ 大多数人 20 分钟就走，其实          │
│         │    沿栈道走到底只要 15 分钟           │
│         └──────────────────────────────────────┘
│
├─ 12:30  ● 午餐 · 就近
└─ 16:00  ● 抵达大柴旦
```

**注意**：**L1–L4 是同一页面上的同一段内容，只是折叠与展开。** 没有跳转、没有"查看详情"、没有第二个页面。

> 🔴 **「没有第二个页面」是一条硬规则。**
>
> 因为**公路场景下的网络不可靠**，也因为**多一次跳转就多一次迷失的可能**。
>
> **折叠是原地展开，跳转是离开。** 用户展开完还要能立刻回到原处——**这在手机上尤其重要，因为返回键会丢失滚动位置。**

### 10.3.3 防穿透

折叠面板展开时，**下层内容不允许响应点击**。

> ⚠️ 这是一条来自母本的真实教训。展开的手风琴若未阻止穿透，**用户在展开内容上滑动时，会误触到下层的卡片并跳走**——而用户完全不知道发生了什么，只觉得"这破玩意儿乱跳"。
>
> **这是典型的[静默失败](00-overview-and-glossary.md#铁律-8--拒绝静默失败-never-fail-silently)**：用户误触后页面变了，但没有任何东西告诉他"是你碰到了下面那层"。

## 10.4 时间轴的设计

### 10.4.1 时间轴要处理的核心问题：不确定的时间

**行程表假设每一站都准时。但现实中从来不是。**

| 情况 | 行程表怎么做（错） | 路书怎么做 |
| :--- | :--- | :--- |
| 「约 40 分钟」 | 写 `09:40–10:20` | 写 `09:40 → 约 40 分钟` |
| 「看情况」 | 编一个时间 | 写 `傍晚` 或 `待定` |
| 「可能会玩很久」 | 写死时长 | 标 **⏳ 弹性**，并说明为什么 |

> 📌 **时间轴必须能表达"不确定"本身。**
>
> 一份把每个停留都写成精确时刻的路书，**在第一次延误之后就废了**——因为后面所有时间都不可信，用户就再也不看时间轴了。
>
> **而一份写着「上午」「约 1 小时」「弹性」的路书，晚了一个小时仍然是准的。**

### 10.4.2 时间轴的三种节点

| 类型 | 符号 | 含义 | 视觉 |
| :--- | :---: | :--- | :--- |
| **锚点** | ● | 有约束的（航班、开餐、关门） | 实心、重 |
| **游览** | ○ | 可伸缩的 | 空心、轻 |
| **过渡** | ┄ | 行车、休息、加油 | 虚线、最轻 |

> 📌 **三者的视觉权重必须拉开。** 用户扫时间轴时，**眼睛应该先看到 ● ，再看到 ○ ，最后才注意到 ┄**。
>
> **因为 ● 是不能迟到的，⌀ 是可以商量的，┄ 是会自动发生的。** 这个优先级必须由视觉传达，不能靠用户读文字判断。

### 10.4.3 ★ 时间轴上的"坑"标记

**这是路书上最有价值、也最少见的一类信息。**

| 标记 | 含义 | 例子 |
| :--- | :--- | :--- |
| ⛽ | 加油 | 「出城前加满，之后 180km 无站」 |
| 🚻 | 厕所 | 「之后 2 小时没有」 |
| ⚠️ | 风险 | 「这段有横风，注意方向盘」 |
| 📵 | 无信号 | 「这一段约 1 小时没信号」 |
| 🍽️ | 吃饭 | 「过了这个点，下一顿在 4 小时后」 |
| 🅿️ | 停车 | 「观景台车位只有 8 个，晚了没位」 |

> 🔴 **这类信息是"过来人经验"，不是"公开数据"。**
>
> 「莫高窟开放时间 8:00–18:00」是公开数据，任何产品都能给。
> **「出城前加满，之后 180km 无站」是有人真的跑过这段路才知道的。**
>
> **路书的价值密度，主要就在这一类信息上。** 这也是 [§10.7 数据来源](#107-数据的来源与置信度)要解决的问题。

## 10.5 三种阅读场景

### 10.5.1 同一份路书，三个完全不同的时刻

> 🔴 **这是本章最重要的洞察：**
>
> **路书不是"被读一次"的。它在三个时刻被读，而这三次的读法完全不同——设备不同、网络不同、心态不同、要的东西也不同。**

| | **行前** | **行中** | **旅后** |
| :--- | :--- | :--- | :--- |
| 何时 | 出发前 1 周~1 天 | 出发当天早上 / 车上 | 回来之后 |
| 设备 | 电脑 / 手机 | **手机（车上、阳光下）** | 手机 |
| 网络 | 好 | **差 / 无** | 好 |
| 心态 | 比较、修改、期待 | **赶时间、有点紧张** | 回忆、分享 |
| 读法 | **通读全局** | **只看今天** | **重看一遍** |
| 要什么 | 全局视图、改起来快 | **离线、大字、快速定位** | 照片、足迹 |
| 状态 | 可编辑 | **只读** | 可编辑（补注） |

### 10.5.2 行中模式的四条设计

**行中是最苛刻的场景，所以它的设计优先级最高。**

| # | 设计 | 为什么 |
| :--- | :--- | :--- |
| 1 | **打开就是今天** | 不要让用户在车上翻到 D3。**默认停在今天，其他天折叠到上下** |
| 2 | **全量离线** | 隧道、无人区——**恰恰是最需要它的时候** |
| 3 | **司机模式：一句话** | 司机不能读长文。**提供一个"副驾可以直接念出来"的一句话摘要** |
| 4 | **只读，但可批注** | 行中改行程会造成混乱；但**记录实际发生的事**（"实际 10:20 才到"）很有价值，且是[旅后回忆录](06-memory-journal-engine.md)的原料 |

**行中模式的当日摘要卡**：

```text
┌─────────────────────────────────────────────┐
│  今天 · D3                                   │
│                                             │
│  敦煌到大柴旦，320 公里，开 4 个半小时。      │
│  路上停两个点，玉门关和雅丹。                 │
│  出城前记得加满油，之后 180 公里没加油站。     │
│                                             │
│  [ 看详情 ]                                  │
└─────────────────────────────────────────────┘
```

> 📌 **这段话是给副驾念的。** 三句话，司机听完就知道今天怎么回事。
>
> **它不提供任何新信息**——所有内容都在 L2/L3 里。**它提供的是"不用读就能知道"。**
>
> **这是司机这个用户角色的专属设计。** 在"司机不能看屏幕"这个约束下，**语音是唯一出路，而语音的原料是文字稿。** 提供文字稿，比提供语音播报**更通用**——因为副驾可以直接念，不需要任何功能支持。

### 10.5.3 行前模式

**行前是唯一可以"重"的场景。** 用户在电脑前，有耐心比较。

| 设计 | 说明 |
| :--- | :--- |
| **全览视图** | 一次看到全部天数，便于比较节奏是否均匀 |
| **★ 节奏条** | 一条横向条带显示每天强度——**一眼看出"哪几天太满"** |
| **可编辑** | 改一处只重算一处（[§8.9.3](08-socratic-interaction-design.md#893-生成后的迭代循环)） |
| **打印入口** | 见 §10.6 |

**节奏条的设计**：

```text
D1  ▓▓▓░░░░░░░   轻松
D2  ▓▓▓▓▓▓▓░░░   满
D3  ▓▓▓▓▓░░░░░   偏满
D4  ▓▓▓▓▓▓▓▓▓▓   满 ★ 这天太挤了
D5  ▓▓▓░░░░░░░   轻松
D6  ▓▓▓▓▓▓▓▓░░   偏满
D7  ░░░░░░░░░░   缓冲

           ↑ 点一下可以直接跳到那天
```

> 🔴 **这个「节奏条」是产物上最容易被低估、但价值最高的一个组件。**
>
> 因为**"一份行程累不累"是一个全局性质，用户不可能通过逐天阅读看出来。**
>
> 他读 D1 觉得还行，读 D2 觉得还行……**读完七天，他没法回答"这趟是不是太赶了"。**
>
> **节奏条把七天的强度压缩成一条线，让"累"这件事第一次变得可见。**

## 10.6 其他形态

### 10.6.1 打印形态

**打印不是遗留需求。** 在无人区、在长辈手里、在车里——**纸仍然是最可靠的介质**。

| 约束 | 设计 |
| :--- | :--- |
| A4 竖版 | **一页一天**（不是"排到哪算哪"） |
| 黑白可读 | **颜色不承载任何信息**——状态标记必须同时有图形和文字 |
| 字号 | 打印版比屏幕版**大一档**（纸质阅读距离更远） |
| 折叠 | 折起来能放进手套箱 |
| 页眉 | 印上「第 X 天 / 共 7 天」——**散页后能重新排序** |

> 📌 **「散页后能重新排序」这条来自一个真实的尴尬**：打印出来的路书掉了几页，或者顺序乱了，**用户无法确定哪页是哪天**。
>
> 页码不够，因为页码在装订边上容易被裁掉或遮住。**页眉处印"第 X 天"，是散页后仍能自救的设计。**

### 10.6.2 分享形态

| 场景 | 形态 | 设计要点 |
| :--- | :--- | :--- |
| 微信发给同行者 | 链接 | **不需要登录、不需要装 App**——点开就看（[铁律 5](00-overview-and-glossary.md#铁律-5--无后端可运行-backendless-by-default)） |
| 朋友圈海报 | 一张长图 | **不是截图**，是专门生成的竖版长图：路线 + 天型 + 亮点 |
| 给没去的人看 | 回忆录 | 见 [第 6 章](06-memory-journal-engine.md) |

> ⚠️ **「不需要登录」是一条会损失数据、但必须守住的规则。**
>
> 加了登录，你能拿到用户的手机号；但**同行的一位长辈点开链接，看到"请输入手机号注册"，他就不看了。**
>
> **路书的价值在于被同行的人都看到。** 为了拿一个手机号而损失一半的阅读率，**这笔账是亏的。**

### 10.6.3 离线形态

| 什么必须离线 | 什么可以离线时缺失 |
| :--- | :--- |
| ✅ 全部文字内容 | ⬜ 实时天气 |
| ✅ 自绘骨架地图 | ⬜ 实时路况 |
| ✅ 应急信息（电话、备选路线） | ⬜ 图片（可降级为占位） |
| ✅ 已缓存的图片 | ⬜ 其他天的高清图 |

> 📌 **骨架上必须标出"什么是离线时看不到的"**，而不是让用户以为数据是实时的。
>
> **一个不知道自己在看缓存数据的用户，会因为"前方畅通"的过期信息做出错误决定。** 这是[铁律 8](00-overview-and-glossary.md#铁律-8--拒绝静默失败-never-fail-silently)在产物层的体现。

## 10.7 数据的来源与置信度

### 10.7.1 三种数据，三种待遇

| 类型 | 来源 | 特点 | 呈现方式 |
| :--- | :--- | :--- | :--- |
| **公开事实** | 官方公布 | 稳定、可查证 | 直接陈述 |
| **经验数据** | 母本积累 / 众包 | **会失效** | 标注时间与来源 |
| **AI 建议** | 生成 | **可能错** | 标注为建议，[铁律 7](00-overview-and-glossary.md#铁律-7--事实与建议分离-fact-vs-advice) |

### 10.7.2 ★ "会失效"的信息必须标日期

```text
⛽ 出城前加满 · 之后 180km 无加油站
   来源：母本实测 · 2025-10
   ⓘ 加油站可能新增，出发前建议再确认
```

> 🔴 **不标日期的经验数据，等于把一份可能过期的信息伪装成事实。**
>
> 一条 2023 年记录的"这家店很好吃"，到 2026 年可能已经倒闭了。**用户按它去了，扑空，然后不再相信路书上的任何一句话。**
>
> **标注日期不是免责，是让用户能自己判断可信度。**

## 10.8 本章设计清单

| # | 设计决策 | 一句话 |
| :--- | :--- | :--- |
| R-01 | **路书是剧本，不是行程表** | 要能在第二天早上仍然有用 |
| R-02 | **六种日型标签** | 用户按"天"规划，不按"景点" |
| R-03 | **必设缓冲日** | 把意外提前安排在计划里 |
| R-04 | **标题区只放四个数字** | 超过四个就没人看了 |
| R-05 | **海拔带方向箭头** | 上升是警告，下降是轻松 |
| R-06 | **五层信息深度共存于一处** | 不用做两个版本 |
| R-07 | **L2 默认展开，其余收起** | 默认值回答"用户现在最想知道什么" |
| R-08 | **折叠不用跳转，没有第二个页面** | 跳转会丢失滚动位置 |
| R-09 | **必须防穿透** | 母本的真实教训 |
| R-10 | **时间轴能表达"不确定"** | 精确时刻在第一次延误后就废了 |
| R-11 | **三类节点视觉权重必须拉开** | 不能迟到的 / 可商量的 / 自动发生的 |
| R-12 | **"坑"标记是价值密度最高的部分** | 过来人经验，不是公开数据 |
| R-13 | **同一产物服务三个场景** | 行前 / 行中 / 旅后读法完全不同 |
| R-14 | **行中：打开就是今天** | 不要让用户在车上翻到 D3 |
| R-15 | **司机模式 = 一段可以念出来的话** | 比语音播报更通用 |
| R-16 | **★ 节奏条** | 让"这趟累不累"第一次变得可见 |
| R-17 | **打印页眉印"第 X 天"** | 散页后能自救 |
| R-18 | **分享不需要登录** | 为手机号损失一半阅读率是亏的 |
| R-19 | **必须标出"离线时看不到什么"** | 用户会因过期信息做错误决定 |
| R-20 | **经验数据必须标日期** | 不标日期的经验数据是伪装的事实 |
