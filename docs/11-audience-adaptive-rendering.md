# 第 11 章 · 人群画像驱动的差异化呈现

> **本章性质**：产物呈现设计规格，**不涉及技术实现**。
> **回答的问题**：一车人需求各不相同，同一份路书怎么让每个人都读到该读的？
> **状态**：`Design Spec`

---

## 11.1 设计立场：这不是一次旅行，是三次

### 11.1.1 一个被忽略的事实

README 目前的设计是：**一份路书，全员共读**，外加一个「长辈大字模式」。

**这个设计有一个根本性的错误假设——它假设一车人关心的是同一件事，只是有人需要更大的字。**

但真实情况是：

> **一辆车里坐着的是几场不同的旅行。**
>
> · 六十岁的母亲关心的是：**哪里能坐、哪里有厕所、几点能吃上热饭**
> · 三岁的孩子关心的是：**哪里能跑、什么时候能睡**
> · 摄影的爸爸关心的是：**日落在几点、哪个机位、人少不少**
> · 开车的你关心的是：**下一个加油站在哪、这段路堵不堵、我还能开多久**
>
> **他们看的是同一条路线，但问的是完全不同的问题。**

### 11.1.2 但也不能做成几份文档

**如果给每个人生成一份独立路书，会有更严重的问题：**

| 问题 | 后果 |
| :--- | :--- |
| 汇合点对不上 | 「你说 3 点，我这儿写 3 点半」 |
| 不知道别人为什么慢 | 「为什么要在那等两小时？」 |
| 领队失去全局 | 无法协调 |
| 修改要改五遍 | 改一处要同步五份 |

> 🔴 **群体出行的第一需求不是"各自舒服"，是"别走散"。**
>
> **一份文档的核心价值，是它是所有人共同的事实基础。** 拆成五份，就失去了这个价值。

### 11.1.3 解法：一份主路书 + 五个视角图层

| | 主路书 | 视角图层 |
| :--- | :--- | :--- |
| **内容** | 时间、地点、路线、汇合点、花销 | 与你相关的提醒与细节 |
| **谁看** | **所有人看同一份** | 各自打开自己的 |
| **能否改** | 只有领队能改 | 只影响自己看到的 |
| **作用** | **协调层** — 保证大家说的是同一件事 | **关怀层** — 保证每个人被照顾到 |

> 📌 **一句话：主路书回答「我们几点在哪」，视角图层回答「我该注意什么」。**

## 11.2 五个视角

### 11.2.1 视角总表

| 视角 | 谁 | 关心什么 | 不关心什么 |
| :--- | :--- | :--- | :--- |
| 🧭 **领队**（默认） | 组织者 | **全部** + 协调 + 花销 | — |
| 👓 **长辈** | 60+ / 行动不便者 | 休息 · 厕所 · 热食 · 步行距离 · 台阶 · 海拔 | 拍照机位 · 历史典故 |
| 👶 **带娃** | 有幼童的家长 | 玩耍点 · 午睡窗口 · 吃饭时间 · 厕所 · **安全警示** | 长时徒步 · 需安静的场所 |
| 📷 **摄影** | 为拍照而来的人 | **光线窗口** · 机位 · 人少的时段 · 季节 | 与光线无关的安排 |
| 🚗 **司机** | 握方向盘的人 | 加油 · 路况 · 停车 · 疲劳点 · 无信号段 | 景点介绍 · 拍照 |

> ⚠️ **「司机」这个视角最特殊，因为它唯一不读长文。**
>
> 其他四个视角都是"读得更多或更少"，**只有司机视角是"换一种读法"**——他需要的是**能用一秒钟获取的信息**，和一段**别人能念给他听的话**（[§10.5.2](10-roadbook-reading-design.md#1052-行中模式的四条设计)）。

### 11.2.2 视角从哪来

**不需要用户手动选择。** 视角由 [§8.4.2 药丸系统](08-socratic-interaction-design.md#842-药丸库全集)的输入自动派生：

| 药丸输入 | 派生视角 |
| :--- | :--- |
| ④ 关怀标签「👓 有 60+ 长辈」 | 自动开启 👓 长辈视角 |
| ④ 关怀标签「👶 有幼童」 | 自动开启 👶 带娃视角 |
| ④ 关怀标签「♿ 行动不便」 | 长辈视角**加强模式**（步行距离全部标出） |
| ⑨ 摄影权重「📷 专门为拍照来的」 | 自动开启 📷 摄影视角 |
| ⑤ 载具「自驾」 | 自动开启 🚗 司机视角 |
| ⑩ 体力「走不了太久」 | 影响所有视角的行程强度 |

> 📌 **「不需要手动选择」是刻意的。**
>
> 因为**要照顾谁这件事，用户已经在药丸里回答过了。** 再让他选一遍"要为谁开启视角"，是把同一个问题问两次。
>
> **产品应该把它做出来，而不是再问一次。**

### 11.2.3 视角可以手动开关

**自动派生是默认，但用户可以覆盖。**

| 情况 | 处理 |
| :--- | :--- |
| 用户自己就是摄影师 | 「专门为拍照来的」已开启，无需操作 |
| 用户既开车又拍照 | **两个视角同时开** — 视角可以叠加 |
| 长辈其实身体很好 | 可以关掉长辈视角 |
| 领队想看看"爸妈会看到什么" | **可以预览任意视角** |

> ⚠️ **「领队可以预览任意视角」是一条关键设计。**
>
> 因为领队最常犯的错误不是"忘了照顾谁"，而是**"以为自己照顾到了"**。
>
> **让他能切到长辈视角看一眼，比让他读十遍"已开启长辈关怀"有效得多。**

## 11.3 视角如何改变呈现

### 11.3.1 核心原则：加亮，不是隐藏

> 🔴 **视角图层只做两件事：把相关的**提上来**，把不相关的**沉下去**。**
>
> **它不删除任何东西。**

**为什么不删除？**

因为**理解"别人为什么在意"是群体出行的一部分**。

```text
❌ 长辈视角里删掉了「等日落 2 小时」
   → 长辈不明白为什么要在这耗两小时，会觉得在浪费时间

✅ 长辈视角里标出「这个点其他人要等日落，旁边有休息区和热饮」
   → 长辈知道怎么回事，且知道自己这段时间有着落
```

> 📌 **视角的目的不是"让每个人只看自己的"，而是"让每个人知道自己的部分被安排好了"。**
>
> **这两者的差别，就是"被照顾"和"被隔离"的差别。**

**但有一个例外**：🚗 **司机视角允许隐藏**——因为司机**在开车时读**，任何与驾驶无关的内容都是干扰。

### 11.3.2 每天的「为你」卡片

**视角图层在每一天的开头插入一张小卡**，这是它最显眼的呈现：

```text
┌─────────────────────────────────────────────────────┐
│  👓 今天你要留意的                                   │
│                                                     │
│  · 上午玉门关有风，帽子戴紧                          │
│  · 全程步行约 900 米，都是平路，没有台阶              │
│  · 12:30 能坐下吃热的                                │
│  · D4 那晚住大柴旦，镇上条件一般，但房里有暖气        │
└─────────────────────────────────────────────────────┘
```

**设计规则**：

| 规则 | 说明 |
| :--- | :--- |
| **不超过 4 条** | 超过就变成"又一个要读的段落" |
| **每条都是具体的** | 「有风」→「帽子戴紧」，不是「注意天气」 |
| **说清"有没有"** | 「有台阶」/「没有台阶」——**肯定的否定信息和肯定信息一样重要** |
| **★ 坏消息要直说** | 「镇上条件一般」——不粉饰 |

> 🔴 **最后一条是本设计的信任基础。**
>
> 一个只说好话的关怀系统，用户会很快发现它在**报喜不报忧**，然后**再也不看它**。
>
> **「这晚条件一般，但房里有暖气」** 比 **「舒适住宿体验」** 有价值一百倍——**因为它同时告诉了你坏消息和它还好在哪。**

### 11.3.3 五个视角的「为你」卡片举例

**同一段路（玉门关 → 雅丹，戈壁无人区 180km）**：

| 视角 | 卡片内容 |
| :--- | :--- |
| 👓 **长辈** | 这段 2 小时没有厕所；雅丹有区间车，不用走；带上保温杯，路上没有热水 |
| 👶 **带娃** | 这段 2 小时没信号，**提前给娃下好动画片**；雅丹有护栏，但风大别让娃跑远 |
| 📷 **摄影** | 雅丹日落 19:20，**建议 17:30 到**，这个时段斜光打在西侧土林上；人最多的是正午，下午反而少 |
| 🚗 **司机** | 出城加满油，**之后 180km 无站**；这段有横风，双手扶稳；**1 小时无信号**，导航提前下载 |
| 🧭 **领队** | 全员在雅丹 17:30 集合；摄影组要留到日落（19:40），**其他人可先回**，20:30 酒店碰头 |

> 📌 **注意最后一行——领队的卡片里出现了"分头行动"的安排。**
>
> **这正是 [§8.8 多人冲突](08-socratic-interaction-design.md#88--多人意见冲突的对话设计)在产物层的落地**：冲突不是在生成时被"调和"掉的，而是**被排进日程变成一个明确的、体面的安排**。

## 11.4 ★ 冲突可视化

### 11.4.1 这是多视角系统最有价值的产出

**当多个视角同时开启时，系统能看见单个用户看不见的东西：**

> **某个安排对某个人群是不友好的。**

这是**只有多视角架构才能发现**的问题——**在生成时是看不见的**，因为生成时看的是"路线合不合理"，不是"这个安排对每个人分别意味着什么"。

### 11.4.2 冲突的呈现

```text
⚠️ D4 有个安排可能不合适

   雅丹日落要等到 19:40，回到大柴旦是 22:30。
   · 👓 长辈视角：这天会到很晚，且晚饭在 21:00 之后
   · 👶 带娃视角：孩子的睡觉时间会比平时晚 2 小时

   三个办法：
   [ 改 D5 早上来 ]   [ 长辈和孩子先回，摄影组留 ]   [ 就这样，没关系 ]
```

### 11.4.3 冲突的四种类型

| 类型 | 例子 | 通常解法 |
| :--- | :--- | :--- |
| **体力冲突** | 徒步 4 小时 vs 走不动 | 分组路线 |
| **时间冲突** | 等日落 vs 按时吃饭 | 分头行动 |
| **内容冲突** | 孩子要玩沙 vs 要赶路 | 压缩下一站 |
| **★ 生理冲突** | 21:00 才吃晚饭 vs 长辈的胃 | **必须解决**——这一类不能"就这样吧" |

> ⚠️ **第四类「生理冲突」必须被单独识别并优先解决。**
>
> 前三类冲突的后果是"体验差一点"，**用户可以选择接受**。
>
> **但第四类的后果是身体出问题**——长辈饿到胃疼、孩子困到崩溃。**这类冲突产品不应该给"就这样吧"这个选项。**
>
> **这也是 [§8.10.2](08-socratic-interaction-design.md#8102-什么情况下必须提意见)「安全相关必须提」在产物层的对应。**

## 11.5 视角与三个阅读场景的交叉

**视角不是独立的，它在行前、行中、旅后分别表现不同：**

| | 行前 | 行中 | 旅后 |
| :--- | :--- | :--- | :--- |
| 🧭 领队 | 看全局、改行程、看花销 | 看打卡进度 | 导出账本 |
| 👓 长辈 | 看每天累不累 | **看今天要带什么** | 看照片 |
| 👶 带娃 | 看有没有午睡时间 | **看下一个厕所在哪** | 看孩子的照片 |
| 📷 摄影 | 看光线窗口规划 | **看今天几点到机位** | 看成片和原计划的对比 |
| 🚗 司机 | 看总里程和路线 | **看加油和路况** | 看总行驶数据 |

> 📌 **行中那一列加粗的部分，是每个视角真正的"日常使用"场景。**
>
> **视角的价值 90% 发生在行中**——因为那是唯一一个"当下就能用上"的时刻。
>
> 行前和旅后的视角只是顺带的。**所以视角设计的重点应该放在"行中打开它能立刻得到什么"。**

## 11.6 分享与打印

### 11.6.1 分享单个视角

```text
给爸妈看的版本          →  生成链接，大字、只有长辈视角
给司机的版本            →  生成链接，路况与加油为主
发给全队的              →  主路书，全员视角可切换
```

> ⚠️ **分享出去的视角版本必须是只读的**，且**必须保留主路书的完整信息**——只是**默认展开的部分不同**。
>
> 原因见 [§11.3.1](#1131-核心原则加亮不是隐藏)：**拆散信息会让群体失去共同事实基础。**

### 11.6.2 打印分版本

**打印是唯一一个"视角真正分家"的场景。**

因为打印是**个人副本**——长辈拿着大字纸质版，司机拿着路况版，他们手上本来就是两份纸。

| 版本 | 规格 |
| :--- | :--- |
| **长辈打印版** | 特大字、每天一页、**步行距离与厕所位置用最粗的字** |
| **司机打印版** | 路况与加油为主，**每天一行摘要**，A5 可夹在遮阳板上 |
| **领队打印版** | 完整版（[§10.6.1](10-roadbook-reading-design.md#1061-打印形态)） |

| # | 设计决策 | 一句话 |
